Quick start

Từ source tới relay.

Copy nguyên block sau; cursor cần được lưu riêng ở ứng dụng/job thực.

terminal · bash
# Build
$ cargo build --locked --release

# Local replica
$ novadb init laptop.db
$ novadb exec laptop.db 'CREATE TABLE notes (
    id TEXT COLLATE BINARY PRIMARY KEY,
    title TEXT NOT NULL
);'
$ novadb sync-enable laptop.db notes --primary-key id
$ novadb exec laptop.db "INSERT INTO notes VALUES ('n1','Xin chào');"

# Server in another terminal
$ NOVADB_BEARER_TOKEN=dev-secret novadbd \
    --database-path state/relay.sqlite3 \
    --data-dir state/databases

# Push
$ NOVADB_TOKEN=dev-secret novadb push laptop.db \
    --remote http://127.0.0.1:8787 \
    --database notes-demo
01
Rust 1.85+Linux/Windows/macOS, x64/ARM64 CI.
02
INTEGER hoặc TEXT+BINARY PKMột writable PK; synced TEXT phải valid UTF-8.
03
First enable backfillsExisting rows được capture atomically.
04
Persist 2 cursorsLocal push và remote pull độc lập.

Architecture

Không viết lại điều SQLite đã làm tốt.

NovaDB tập trung vào replication, lifecycle và operator surface; SQLite giữ SQL/storage/recovery cục bộ.

Relay và managed SQL là hai data plane riêng. Push không tự execute vào server database.

Sync semantics

At-least-once delivery. Idempotent apply.

Ba con số dễ bị gọi chung là cursor nhưng thuộc ba domain khác nhau.

local seq_novadb_changes.seq của origin; lưu sau push được account đầy đủ.
relay cursorGlobal insertion order ở server; có thể gap giữa database IDs.
pull cursorCursor cuối replica này đã apply bền vững; lưu sau commit.
Không dùng cursor trả về từ push làm pull cursor. Nó có thể skip change của replica khác. Cursor cũ chỉ gây duplicate; cursor quá mới có thể mất data.

Roadmap, not promises
