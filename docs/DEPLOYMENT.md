# NovaDB: Production Operations and Deployment Guide

> Maintained versions: [Binary and systemd](https://hoangtuvungcao.github.io/NovaDB/deployment/binary-systemd), [Docker](https://hoangtuvungcao.github.io/NovaDB/deployment/docker),
> [Kubernetes](https://hoangtuvungcao.github.io/NovaDB/deployment/kubernetes) (manifests in [`deploy/kubernetes`](../deploy/kubernetes)),
> [Security hardening](https://hoangtuvungcao.github.io/NovaDB/deployment/security), [Backups](https://hoangtuvungcao.github.io/NovaDB/guides/backups).

This guide covers deployment, process supervision, backups, Docker containerization, and performance tuning for production environments.

---

## 1. Automated Installation on Linux / macOS

Run the official installer script:

```bash
curl -fsSL https://raw.githubusercontent.com/hoangtuvungcao/NovaDB/master/scripts/install.sh | sudo bash
```

The script downloads the release archive (or builds from source when run inside a checkout) and installs:
* CLI binary to `/usr/local/bin/novadb`
* Server daemon to `/usr/local/bin/novadbd`
* Data directory at `/var/lib/novadb`

When run as root on a systemd Linux host it also creates:
* Credentials at `/etc/novadb/novadb.env` (mode `600`, generated once and kept on reinstall): `NOVADB_BEARER_TOKEN`, `NOVADB_PG_USER=novadb`, `NOVADB_PG_PASSWORD`
* Systemd unit `/etc/systemd/system/novadb.service` (start with `sudo systemctl enable --now novadb`)

## 2. Running as a Systemd Daemon

### 2.1 Configuration File (`/etc/novadb/novadb.env`)
```ini
NOVADB_BEARER_TOKEN=prod_secure_token_change_this_immediately
NOVADB_PG_USER=admin
NOVADB_PG_PASSWORD=prod_db_password_secret
# Optional hardening knobs (read directly by novadb serve / novadbd)
NOVADB_CORS_ORIGINS=https://app.example.com,https://admin.example.com
NOVADB_REQUEST_TIMEOUT_SECS=30
NOVADB_PG_AUTH_METHOD=scram-sha-256
NOVADB_PG_MAX_CONNECTIONS=100
# MySQL wire gateway (enabled with --mysql-listen)
NOVADB_MYSQL_USER=app
NOVADB_MYSQL_PASSWORD=prod_mysql_password_secret
NOVADB_MYSQL_MAX_CONNECTIONS=100
```

### 2.1.1 Safe Exposure Rules
The server refuses to start when a listener is reachable from the network without credentials:
* `--listen` on a non-loopback address (e.g. `0.0.0.0`) requires a bearer token (`NOVADB_BEARER_TOKEN` / `--bearer-token`).
* `--pg-listen` on a non-loopback address requires `--pg-password` (`NOVADB_PG_PASSWORD`).
* `--mysql-listen` on a non-loopback address requires `--mysql-password` (`NOVADB_MYSQL_PASSWORD`).
* Pass `--allow-insecure` (or `NOVADB_ALLOW_INSECURE=true`) only for trusted private networks.

Other hardening flags (identical for `novadbd` and `novadb serve`):
* `--cors-origin <ORIGIN>` (repeatable, or `NOVADB_CORS_ORIGINS` comma-separated): allow browser apps on those origins; `*` allows any. CORS is off by default.
* `--request-timeout-secs <N>` (default `30`): HTTP requests exceeding it receive `408`.
* `--pg-auth-method scram-sha-256|md5|password` (default `scram-sha-256`).
* `--pg-max-connections <N>` (`novadbd` default `1000`, max `100000`): further PostgreSQL clients are rejected with SQLSTATE `53300`.
* `--mysql-listen <ADDR>` (conventionally port `3306`): enables the MySQL wire gateway ([MYSQL.md](MYSQL.md));
  `--mysql-user` / `--mysql-password` set credentials and `--mysql-max-connections <N>` (`novadbd` default `1000`, max `100000`) caps
  clients (extra ones receive MySQL error `1040`). The gateway runs as an independent task: if it fails, the
  HTTP API keeps serving. It has no TLS; terminate TLS in a proxy for remote access.

HTTP requests are logged at INFO through `tower_http` (method, URI, status, latency; headers such as `Authorization` are never logged). Adjust with `RUST_LOG`, e.g. `RUST_LOG=novadb_server=info,novadb_wire=info,novadb_mysql=info,tower_http=warn`.

### 2.2 Systemd Unit File (`/etc/systemd/system/novadb.service`)

Generated by the installer:

```ini
[Unit]
Description=NovaDB Server and PostgreSQL Wire Protocol Gateway
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/var/lib/novadb
EnvironmentFile=/etc/novadb/novadb.env
ExecStart=/usr/local/bin/novadbd --listen 0.0.0.0:8787 --pg-listen 0.0.0.0:5432 --data-dir /var/lib/novadb
Restart=always
RestartSec=3
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

To also serve MySQL clients, append `--mysql-listen 0.0.0.0:3306` to `ExecStart` (and set
`NOVADB_MYSQL_PASSWORD`).

`novadbd` reads `NOVADB_BEARER_TOKEN`, `NOVADB_PG_USER`, `NOVADB_PG_PASSWORD`, `NOVADB_MYSQL_USER`,
`NOVADB_MYSQL_PASSWORD` and the optional variables above
from the environment. To run as a dedicated non-root user with sandboxing, use the drop-in shown in the
[systemd guide](https://hoangtuvungcao.github.io/NovaDB/deployment/binary-systemd).

### 2.3 Service Commands
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now novadb
sudo systemctl status novadb
```

## 3. Docker & Docker Compose Deployment

### 3.1 Docker Compose

The repository ships [`compose.yaml`](../compose.yaml). It builds the image from the `Dockerfile` (non-root uid
10001, data in the `/var/lib/novadb` volume), requires `NOVADB_BEARER_TOKEN`, and health-checks `/health`:

```bash
echo "NOVADB_BEARER_TOKEN=$(openssl rand -hex 32)" > .env
docker compose up -d
```

The PostgreSQL gateway is off by default in the container. To enable it, uncomment the `NOVADB_PG_*` variables,
the `command:` line (which adds `--pg-listen 0.0.0.0:5432`) and the `5432` port in `compose.yaml`.
The MySQL gateway is enabled the same way: add `--mysql-listen 0.0.0.0:3306` to the command, set
`NOVADB_MYSQL_PASSWORD`, and publish port `3306`.

## 4. Hot Online Backups and Disaster Recovery

NovaDB supports live online backups without locking out readers or writers:

### 4.1 CLI Backup Command
```bash
# Automated cron hot backup
novadb backup /var/lib/novadb/default.novadb /backups/default-$(date +%F_%H%M%S).novadb
```

### 4.2 Automated Daily Cron Backup
```bash
0 2 * * * novadb backup /var/lib/novadb/default.novadb /backups/default-$(date +\%F).novadb && find /backups -name "*.novadb" -mtime +14 -delete
```

### 4.3 Disaster Recovery
Restoring a database is an atomic file copy:
```bash
# Stop service
sudo systemctl stop novadb

# Restore snapshot
cp /backups/default-2026-08-24.novadb /var/lib/novadb/default.novadb

# Verify integrity
novadb integrity /var/lib/novadb/default.novadb

# Restart service
sudo systemctl start novadb
```

## 5. Performance Optimization & Tuning

### 5.0 Large multi-user servers (`novadbd`)
SQLite allows exactly one writer per database file; everything else is parallel. HTTP reads use a per-database pool of
`query_only` WAL readers; autocommit writes from many clients are group-committed (several statements share one
transaction, each keeps its own result/error). Flags (env in parentheses, `NOVADB_` prefix):

| Flag | Default | Meaning |
|---|---|---|
| `--read-pool-size` (`READ_POOL_SIZE`) | CPU count | Reader connections per database, opened lazily. |
| `--no-group-commit` / `--group-commit-max-batch` / `--group-commit-max-wait-us` | on / 128 / 200 | Group commit of concurrent autocommit writes (HTTP `/sql/execute`, PG/MySQL autocommit). Explicit transactions, DDL, temp tables and sessions with `FOREIGN_KEY_CHECKS=0` bypass it. |
| `--max-sql-bytes` | 16 MiB | Largest SQL text for `/sql/execute`, `/sql/query`, migrations. |
| `--max-request-body-bytes` | 64 MiB | Largest HTTP body. |
| `--max-connections` | 10000 (`0` = unlimited) | Open HTTP connections; the surplus waits in the accept backlog. |
| `--listen-backlog` | 4096 | `listen(2)` backlog for HTTP/PG/MySQL (also bounded by `net.core.somaxconn`). |
| `--max-result-rows` / `--max-result-bytes` | 1,000,000 / 512 MiB | `/sql/query` fails with `413` instead of truncating; page with `LIMIT`/`OFFSET` or keyset (`WHERE id > ? ORDER BY id LIMIT n`). |
| `--pg-max-connections` / `--mysql-max-connections` | 1000 (max 100000) | Gateway sessions; each is one SQLite connection. |
| `--lookaside-kib` | automatic | Per-connection SQLite lookaside memory. Automatic: 600 KiB for the first 64 connections, then 150 KiB (75 KiB beyond 4096); the page cache shrinks the same way. |
| `--worker-threads` / `--max-blocking-threads` | CPU count / max(4096, gateway caps + 512) | Tokio runtime. Gateway sessions run DB calls on the blocking pool; it is sized so waiting writers can never starve readers. |

Protection and observability flags (details in API.md):

| Flag | Default | Meaning |
|---|---|---|
| `--statement-timeout-ms` (`STATEMENT_TIMEOUT_MS`) | 30000 (`0` = off) | Interrupts statements that run longer; only that statement fails (HTTP `408`). |
| `--max-write-transaction-ms` (`MAX_WRITE_TRANSACTION_MS`) | 60000 (`0` = off) | Rolls back gateway-session transactions holding the write lock too long. |
| `--slow-query-ms` (`SLOW_QUERY_MS`) | 500 (`0` = off) | `warn` log of slow statements, literals redacted. |
| `--metrics-public` (`METRICS_PUBLIC`) | off | Serve `GET /metrics` (Prometheus) without the bearer token. |

Write scaling: one database file tops out at one commit pipeline. For more, create a sharded database
(`POST /v1/admin/databases/game?shards=N`, see API.md "Sharded databases") and route requests by player key.
Use bound parameters (`params`) and `/sql/batch` from the game server: they avoid per-statement SQL parsing and
extra round trips.

Raise the file-descriptor limit (`ulimit -n` / systemd `LimitNOFILE=`) to at least 2x the expected connections.
`/sql/execute` responses now also carry `changes` and `last_insert_rowid` of the request's last statement.


### 5.1 Memory & WAL Settings
NovaDB uses Write-Ahead Logging (WAL) by default. For high throughput:
* Checkpoint WAL periodically during low-traffic windows: `novadb checkpoint <db>`
* Read Pool: Adjust connection pool size (`NovaDbPool::open(path, reader_count)`) according to CPU core count (typically `2 * CPU_CORES`).
* Disk Storage: Ensure database storage is on SSD/NVMe drives with `noatime` mount options.
